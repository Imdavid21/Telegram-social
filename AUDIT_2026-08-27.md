# Supergram system audit

Date: 2026-08-27
Scope: connected product shell, feed, settings, search, media, Telegram gateway, authentication/session handling, local persistence, and optional OpenAI summaries.

## Executive status

The BYOK summary path is now privacy-first: local summaries are the default, there is no shared OpenAI key or server-side model route, user keys remain in page memory only, OpenAI is opt-in, private-chat summarization is separately opt-in, and model failure falls back locally.

The largest remaining product risk is UI-system debt rather than a single broken screen. The runtime still imports many generations of CSS, so later styles can silently override earlier ones. This should be consolidated after visual regression coverage exists.

## UI and UX audit

### High priority

1. **Layered CSS architecture**. `main.tsx` imports shadcn, styles, production, feed, feed-engine, landing, demo, identity, app-system, session-boot, ux-overhaul, instagram-desktop, backend-search, and social-system styles. This creates order-dependent behavior and makes responsive regressions difficult to reason about. Do not delete these blindly. First move live product-shell rules into one owned layer and add screenshot coverage for desktop, tablet, and mobile.
2. **Navigation semantics overlap**. Desktop exposes Home/Discover/Activity/Saved plus Search, Chats, All sources, Settings, and an account button that also opens Settings. Chats and All sources lead to the same source browser, while account and Settings lead to the same dialog. Consolidate to one Sources/Chats entry and one profile/settings entry.
3. **Discover is currently a media filter**. The label promises discovery, but the underlying filter is `media`. Either rename it Media or implement actual discovery/search behavior.
4. **Activity is currently unread content**. The label implies reactions, mentions, and social events, but maps to the `unread` feed filter. Rename it Unread until the activity system is actually wired into this shell.
5. **OpenAI key lifecycle must be visible**. The key now clears on refresh. Settings copy explicitly says this. Do not persist it without a separate threat-model review.

### Medium priority

6. Feed mode labels use `For You` and `Following`, while the internal second mode is `latest`. Following is only accurate if the feed truly contains followed sources and is chronological. Verify source semantics.
7. Search has two scopes, loaded results and Telegram history. Keep the distinction visually explicit and never imply that a loaded-feed miss means Telegram has no result.
8. Source browser, search overlay, settings dialog, bottom sheets, and media lightbox all compete for modal state. Ensure opening one closes or suspends the others and restores focus to the trigger.
9. Keyboard feed navigation needs to ignore active inputs, dialogs, and textareas, and preserve the current virtualized-item anchor.
10. Empty states should distinguish no data, active filter with no matches, network failure, and exhausted pagination. Existing copy mostly does this but needs regression coverage.
11. Optimistic reaction/save actions need explicit rollback on network failure and should not double-submit under rapid tapping.
12. New-post buffering must not move the reading position. Applying queued posts should preserve the visible anchor.
13. Media cards need stable aspect-ratio placeholders to prevent layout shift when images/video metadata arrives late.
14. Autoplay must respect reduced-motion/data-saving expectations and stop playback when media leaves the viewport.
15. Very long channel names, usernames, captions, URLs, filenames, and unbroken strings need overflow tests at 320px width.
16. RTL, non-Latin scripts, emoji-heavy messages, and mixed-direction Telegram content need visual tests.
17. Very large unread counts and missing avatars need deterministic compact rendering.
18. Deleted/edited messages arriving through incremental updates must not leave stale open discussions, search results, or lightboxes.
19. Expired pagination cursors are recovered, but the recovery path should preserve the user's scroll position and current filter.
20. The right context rail should collapse before the main feed becomes too narrow; verify at common laptop widths and browser zoom levels.

### Accessibility and interaction

21. All icon-only controls need stable accessible names. Continue using `aria-label` rather than relying on title tooltips.
22. Dialogs and sheets need focus trapping, Escape close, trigger-focus restoration, and scroll locking. Radix covers the Settings dialog; custom overlays need equivalent behavior.
23. Visible focus styles must survive every CSS layer and theme.
24. Touch targets should be at least approximately 44px on mobile, especially feed actions and bottom navigation.
25. Color must not be the only signal for unread, selected, warning, scam/fake, success, or failure states.
26. Verify contrast in both light and dark themes, including muted metadata and disabled controls.
27. Announce asynchronous errors, new-post counts, and save/reaction confirmation through appropriate live regions without excessive chatter.

## Privacy and security audit

### Fixed in this branch

1. Removed the dedicated server-side summary endpoint.
2. Removed the gateway's shared `OPENAI_API_KEY` summarization path.
3. OpenAI summaries now require a user-provided API key.
4. The OpenAI key is held in module memory only. It is not written to localStorage, sessionStorage, Redux, URL state, logs, or the Supergram backend.
5. OpenAI requests are browser-to-OpenAI and set `store: false`.
6. Private-chat summarization remains disabled by default and requires a separate opt-in.
7. Local summarization remains the default and fallback.
8. Privacy copy now discloses OpenAI processing and the residual risk of secrets used in a browser context.

### Existing positive controls

9. Telegram session material is encrypted with AES-256-GCM before being placed in the session cookie.
10. Production requires a 32+ character backend proxy secret and uses timing-safe comparison.
11. Production write requests perform origin checks when an Origin header is present.
12. Telegram login attempts are rate-limited by IP.
13. Express disables `x-powered-by` and limits JSON request bodies to 32 KB.
14. Session cookies are HttpOnly, Secure in production, and SameSite=Lax.
15. Media tickets and feed cursors have bounded lifetimes.

### Remaining security concerns

16. **Browser BYOK is inherently exposed to page compromise**. In-memory storage reduces persistence risk but cannot protect a key from same-origin XSS or a malicious browser extension. Keep the app free of arbitrary third-party scripts and avoid dangerouslySetInnerHTML for Telegram content.
17. **Content Security Policy**. Add a strict CSP at the hosting edge. At minimum constrain scripts to self, network connections to the Supergram API/Telegram backend path plus `https://api.openai.com` when BYOK is used, images/media to required origins, and prohibit object embedding. Test before enforcing because Telegram media delivery may require additional sources.
18. **Origin enforcement**. Production state-changing backend requests currently reject a bad Origin but permit a missing Origin. The private gateway secret is a strong compensating control, but defense in depth would require either the configured public origin for browser writes or a CSRF token bound to the session.
19. **Rate limiting**. Login is rate-limited, but search, media-ticket creation, forwarding, replies, reactions, and other mutation endpoints should have per-session/IP abuse limits to protect Telegram accounts and infrastructure.
20. **Client error logging**. Client error payloads include up to 5,000 characters of stack. Ensure message text, API keys, cookies, auth codes, and request bodies can never be included. Add redaction before logging if richer telemetry is introduced.
21. **Local personalization data**. Viewer actions, saved/read state, favorites, and hidden-source IDs persist in localStorage. They are not message bodies, but they can reveal usage patterns to any script running on the origin. Document and provide a one-click clear-local-data control.
22. **Session lifetime**. A 30-day encrypted Telegram session cookie is convenient but increases exposure on a compromised device. Consider a user-selectable shorter session or explicit 'log out on this device' semantics.
23. **Proxy path allowlist**. The Vercel gateway currently forwards arbitrary `/api/<path>` values to the private backend. Prefer an explicit allowlist of public backend routes so newly added internal backend endpoints are not automatically exposed through the gateway.
24. **Security headers**. Verify HSTS, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, frame-ancestors, and CSP at both Vercel and Railway edges.
25. **Open redirects and external links**. Continue using controlled Telegram post URL construction and `rel="noreferrer"` for new tabs. Validate sponsored URLs and any backend-provided external URLs before rendering them as navigable links.
26. **Dependency hygiene**. Add automated dependency review/Dependabot and run `npm audit` in CI with a policy for actionable high/critical issues.
27. **Secret scanning**. Enable GitHub secret scanning/push protection where available. Never accept OpenAI or Telegram secrets in issues, telemetry, or client error reports.
28. **Privacy deletion semantics**. Disconnecting Telegram should clear server/client session state. Add a separate clear-local-data action for preferences, read/saved state, favorites, hidden sources/posts, and viewer actions.

## Edge-case regression matrix

Test signed out, first login, invalid phone, invalid code, 2FA, expired auth flow, revoked Telegram session, backend unavailable, slow backend, no dialogs, thousands of dialogs, archived dialogs, empty channels, private chats disabled from For You, private summary disabled, BYOK missing, BYOK invalid, OpenAI quota error, OpenAI timeout, page refresh after key entry, 320px mobile, tablet split width, 200% zoom, reduced motion, offline/reconnect, expired cursor, deleted message, edited message, album, huge video, unsupported document, no-forward post, sponsored message, scam/fake source, RTL text, very long unbroken text, and rapid repeated actions.

## Release gate

Before calling this branch production-ready: CI build/typecheck must pass, no shared OpenAI key path may remain, privacy copy must match implementation, and the deployment should be smoke-tested on mobile and desktop. CSS consolidation is a separate refactor and should not be done by deleting legacy files without visual regression coverage.
